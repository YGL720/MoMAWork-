第 11 章 文件与目录：整理、搜索、批量处理 ​

11.1 场景 ​

电脑里的文件越堆越多，找东西越来越难。文件类任务包括：

  • 整理：归档、重命名、统一格式；
  • 搜索：按文件名找、按内容找；
  • 批量处理：成百上千个文件的统一操作。

11.2 找文件：用对工具 ​

需求工具示例
按文件名/扩展名找Glob**/*.md 找所有 Markdown
按内容找Grep搜 "TODO" 或函数名
看目录结构目录列表了解项目布局
看文件内容Read读具体文件

黄金法则：找文件用 Glob，搜内容用 Grep。 不要让我用命令行的 find/grep 绕路——专用工具更快、更安全、更好追踪。

11.3 案例：整理一个混乱的下载目录 ​

指令：

整理 downloads/ 目录：
- 图片 → 按年月归档到 photos/2026-08/
- 文档 → 按类型归档到 docs/{pdf,word,sheet}/
- 其他 → 移到 archive/
先给出整理计划（会移动哪些文件），我确认后再执行。

我的做法：

  1. 先列出目录全貌（文件数、类型分布）；
  2. 生成"整理计划表"：每个文件的去向你都能看到；
  3. 你确认后执行；
  4. 输出变更日志（哪些文件去了哪里），可回退。

11.4 批量处理：安全第一 ​

批量操作最容易出事，所以规矩更多：

  • 先统计后动手："共有 342 个文件要移动"；
  • 先试运行：能模拟就先模拟；
  • 保留日志：每一步操作都有记录，可撤销；
  • 不可逆操作前必须确认：删除、覆盖、改名冲突。

11.5 内容搜索的进阶用法 ​

  • 正则表达式：err.*\d{4} 精确匹配；
  • 大小写不敏感：搜 readme 时同时匹配 README；
  • 限定文件类型：只在 *.rs 或 *.md 里搜；
  • 多个条件组合：一次搜多个模式。
例：在 src/ 里搜所有包含 "TODO" 或 "FIXME" 的代码行

11.6 练习 ​

  1. 让我用 Glob 列出某个目录下的全部文件，按类型统计；
  2. 给我一个真实的整理需求，要求"先出计划再执行"；
  3. 用 Grep 搜一个你关心的关键词，看看有什么发现。

小结：文件任务的精髓是**"先看清楚，再动手，动完留痕"**。批量操作不怕慢，就怕不可逆。
